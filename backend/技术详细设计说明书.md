## 1. 项目概述

### 1.1 项目背景
微信购物商城小程序后端服务，为微信小程序提供完整的商品浏览、购买、支付、售后一体化购物体验的后端支撑。

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 语言 | Go 1.21+ | 高性能、高并发 |
| Web框架 | Gin | 轻量级、高性能 |
| ORM | GORM | Go语言ORM |
| 数据库 | MySQL 8.0 | 主数据库 |
| 缓存 | Redis 7.x | 会话、热点数据缓存 |
| 配置文件 | Viper | YAML配置管理 |

| 微信SDK | wechatpay-go | 微信支付 |

## 3. 数据库设计

### 3.0 关键领域口径（与 PRD v1.3 / 高保真原型对齐）

为避免“UUID 主键 vs 区域编码（EC/NE…）”在前后端、配置、日志、排查中产生混乱，本设计 **对外 API 与业务层统一使用 `region_code`**（如 `EC`、`NE`）。数据库仍可保留 `id(UUID)` 作为内部主键或扩展字段，但**所有跨表关联与接口入参/出参以 `region_code` 为准**。

- **`region_code`**：短码（`EC/NC/SC/NE/...`），对外暴露、稳定、可读。  
- **`region_id(UUID)`**：内部实现细节（可保留）；若保留，不再作为业务关联键使用。

### 3.1 核心表结构

#### 3.1.1 用户表 (users)

```sql
CREATE TABLE users (
    id              VARCHAR(36) PRIMARY KEY COMMENT '用户ID',
    open_id         VARCHAR(128) UNIQUE COMMENT '微信openid',
    nickname        VARCHAR(100) COMMENT '用户昵称',
    avatar          VARCHAR(500) COMMENT '头像URL',
    phone           VARCHAR(20) COMMENT '手机号',
    status          TINYINT DEFAULT 1 COMMENT '状态: 1正常 0禁用',
    last_login_at   DATETIME COMMENT '最后登录时间',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted_at      DATETIME DEFAULT NULL,
    INDEX idx_open_id (open_id),
    INDEX idx_phone (phone)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

#### 3.1.2 区域表 (regions)

```sql
CREATE TABLE regions (
    id              VARCHAR(36) DEFAULT NULL COMMENT '内部ID(可选)',
    region_name     VARCHAR(50) NOT NULL COMMENT '区域名称如华东、东北',
    region_code     VARCHAR(20) PRIMARY KEY COMMENT '区域编码如EC、NE(对外唯一标识)',
    is_enabled      TINYINT DEFAULT 1 COMMENT '是否启用',
    sort_order      INT DEFAULT 0 COMMENT '排序',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_enabled (is_enabled),
    INDEX idx_sort (sort_order)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='区域表';
```

#### 3.1.4 商品表 (products)

```sql
CREATE TABLE products (
    id              VARCHAR(36) PRIMARY KEY,
    name            VARCHAR(200) NOT NULL COMMENT '商品名称',
    description     TEXT COMMENT '商品描述',
    main_image      VARCHAR(500) COMMENT '主图URL',
    images          JSON COMMENT '图片列表',
    category_id     VARCHAR(36) COMMENT '分类ID',
    price           DECIMAL(10,2) NOT NULL DEFAULT 0 COMMENT '冗余字段: 价格(默认SKU最低价，用于列表加速，可由服务层/定时任务刷新)',
    original_price  DECIMAL(10,2) DEFAULT NULL COMMENT '冗余字段: 划线价(默认SKU或商品级展示，可由服务层刷新)',
    stock           INT DEFAULT 0 COMMENT '冗余字段: 总库存(所有启用SKU库存之和，用于列表加速，可由服务层/定时任务刷新)',
    sales_count     INT DEFAULT 0 COMMENT '销量',
    is_on_shelf     TINYINT DEFAULT 1 COMMENT '是否上架:1上架 0下架',
    show_on_home    TINYINT DEFAULT 1 COMMENT '是否在首页展示(与原型对齐，默认1)',
    available_regions JSON COMMENT '可售区域region_code列表，如[\"EC\",\"NE\"]',
    tags            JSON COMMENT '标签如营销标签',
    promo_text      VARCHAR(200) COMMENT '促销文案',
    low_stock_threshold INT DEFAULT 10 COMMENT '低库存预警阈值',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted_at      DATETIME DEFAULT NULL,
    INDEX idx_category (category_id),
    INDEX idx_on_shelf (is_on_shelf),
    INDEX idx_show_home (show_on_home),
    INDEX idx_sales (sales_count DESC)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品表';
```

#### 3.1.6 库存冻结/预占表 (stock_reservations)

> 用于满足 PRD 3.5「下单锁库存、支付转扣减、取消/超时释放」以及并发场景一致性。  
> 设计目标：可幂等、可过期、可追溯、可被定时任务扫描回收。

```sql
CREATE TABLE stock_reservations (
    id              VARCHAR(36) PRIMARY KEY,
    order_id        VARCHAR(36) NOT NULL COMMENT '订单ID',
    user_id         VARCHAR(36) NOT NULL COMMENT '用户ID',
    product_id      VARCHAR(36) NOT NULL,
    sku_id          VARCHAR(36) NOT NULL,
    quantity        INT NOT NULL COMMENT '冻结数量',
    status          VARCHAR(20) NOT NULL DEFAULT 'FROZEN' COMMENT 'FROZEN|CONSUMED|RELEASED',
    expire_at       DATETIME NOT NULL COMMENT '冻结过期时间(通常=created_at+15min)',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_order_sku (order_id, sku_id),
    INDEX idx_order (order_id),
    INDEX idx_user (user_id),
    INDEX idx_status_expire (status, expire_at),
    FOREIGN KEY (order_id) REFERENCES orders(id) ON DELETE CASCADE,
    FOREIGN KEY (sku_id) REFERENCES product_skus(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='库存冻结/预占表';
```

## 4. API接口设计

### 4.1 基础信息

| 项目 | 说明 |
|------|------|
| 基础URL | /api/v1 |
| 通讯协议 | HTTPS |
| 数据格式 | JSON |
| 认证方式 | JWT Token / 微信wx.login code |

### 4.2 统一响应格式

```json
// 成功响应
{
  "code": 200,
  "message": "success",
  "data": {}
}

// 分页响应
{
  "code": 200,
  "message": "success",
  "data": {
    "list": [],
    "total": 100,
    "page": 1,
    "pageSize": 20
  }
}

// 错误响应
{
  "code": 400,
  "message": "错误描述",
  "error": "详细错误信息"
}
```

### 4.3 用户模块

| 方法 | 路径 | 说明 | 认证 |
|------|------|------|------|
| POST | /user/wx_login | 微信登录 | 否 |
| POST | /user/profile | 更新用户资料 | 是 |
| GET | /user/info | 获取用户信息 | 是 |

### 4.4 区域模块

| 方法 | 路径 | 说明 | 认证 |
|------|------|------|------|
| GET | /regions | 获取区域列表(启用) | 否 |
| GET | /regions/:code | 获取区域详情(region_code) | 否 |

### 4.5 商品模块

| 方法 | 路径 | 说明 | 认证 |
|------|------|------|------|
| GET | /products | 商品列表(分页/筛选) | 否 |
| GET | /products/:id | 商品详情 | 否 |
| PUT | /products/:id/shelf | 上下架 | 后台 |
| PUT | /products/:id/home | 首页展示开关 | 后台 |
| POST | /products | 添加商品 | 后台 |
| PUT | /products/:id | 更新商品 | 后台 |
| DELETE | /products/:id | 删除商品 | 后台 |

**商品列表筛选参数:**
| 参数 | 类型 | 说明 |
|------|------|------|
| category_id | string | 分类ID |
| keyword | string | 关键词 |
| region_code | string | 区域编码(EC/NE...)；用于筛选“当前区域可售” |
| on_shelf | int | 上架状态 1上架 0下架 |
| show_on_home | int | 首页展示 1是 0否 |

## 5. 核心业务逻辑

### 5.1 微信登录流程

```
1. 小程序调用 wx.login() 获取 code
2. 小程序将 code 发送到后端 /user/wx_login
3. 后端用 code 换取 openid (通过微信 API)
4. 后端查询/创建用户记录
5. 后端生成 JWT Token 返回
6. 小程序后续请求带上 Token
```

### 5.2 创建订单流程

```
1. 校验购物车商品(库存、商品状态、区域可售)
2. 校验收货地址
3. 计算订单金额
4. 幂等校验(client_order_token)
5. 冻结库存(创建预占库存记录)
6. 创建订单记录(status=PENDING_PAY)
7. 返回订单信息
8. 15分钟超时未支付自动取消(定时任务)
```

### 5.3 支付流程

```
1. 用户确认支付
2. 调用 /pay/create 创建预支付单
3. 调用微信统一下单接口
4. 返回支付参数给小程序
5. 小程序调起微信支付
6. 支付成功后微信回调 /pay/callback
7. 后端验签、更新订单状态：PENDING_PAY → PENDING_SHIP；并将冻结库存标记为已扣减(冻结→已扣减)
8. 前端轮询订单状态或被动接收状态更新
```

### 5.4 库存扣减规则

| 阶段 | 库存操作 |
|------|----------|
| 创建订单(PENDING_PAY) | 冻结库存 |
| 支付成功 | 冻结→已扣减 |
| 取消/超时 | 释放冻结 |

### 5.5 首页数据获取

```
1. 获取当前区域region_code(从用户缓存/参数)
2. 获取区域配置的Banner列表
3. 获取主推商品:
   - 规则=自动: 取销量第1的商品
   - 规则=指定: 取指定的商品(需校验可售)
4. 获取商品列表:
   - 筛选: 上架+首页展示+当前区域可售
   - 排序: 销量降序
   - 截取: 取前N条(区域配置，服务端做clamp)
5. 分类筛选(可选): 按首页内分类筛选(category_id)，不传表示「全部」
```

## 6. 安全设计

### 6.1 认证授权

| 需求 | 实现方式 |
|------|----------|
| 用户认证 | JWT Token (有效期7天)，由 `/user/wx_login` 签发 |
| 后台认证 | 管理员 JWT Token（独立签发/独立密钥或同密钥不同 `role` Claim），仅允许访问 `/api/v1/admin/*` 与后台写接口 |
| 密码安全 | 微信登录无需密码 |
| API签名 | 微信支付签名验证 |

#### 6.1.1 权限与鉴权边界（MVP 可落地）
- **Token Claim 约定：** `sub=user_id`、`role=user|admin`、`exp` 过期时间；必要时增加 `admin_id` 与 `scopes`。
- **鉴权中间件：**
  - `/api/v1/*`：默认允许匿名访问公开读接口；需要登录的接口校验 `role=user` 或 `role=admin`。
  - `/api/v1/admin/*`：必须 `role=admin`（后台所有接口统一此前缀）。
  - `/api/v1/products/:id/shelf`、`/api/v1/products/:id/home`、`/api/v1/home/config` 等写接口：必须 `role=admin`（与原型后台一致）。

### 6.2 接口安全

- HTTPS 强制
- 请求限流 (每IP 100次/分钟)
- 参数校验
- SQL注入防护
- XSS防护

### 6.3 敏感信息

- 手机号脱敏显示
- 微信openid不直接暴露
- 日志脱敏处理
