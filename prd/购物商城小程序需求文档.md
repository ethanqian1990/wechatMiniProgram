## 1. 项目概述

### 1.1 项目背景
- 微信小程序购物商城，为微信生态内的商家和消费者提供便捷的移动端购物体验
- 依托微信小程序生态，触达海量微信用户，支持微信支付闭环交易

### 1.2 产品定位
- 面向微信用户的B2C购物商城小程序
- 提供完整的商品浏览、购买、支付、售后一体化购物体验

### 1.3 目标用户
- 微信用户（C端消费者）
- 有明确购物需求或冲动消费场景

### 1.4 核心功能（MVP）
| 模块 | 功能 |
|------|------|
| **区域** | 区域选择、区域化商品展示、区域切换 |
| 首页 | Banner轮播、商品推荐 |
| 分类页 | 商品分类、分类展示 |
| 搜索 | 关键词搜索、商品筛选 |
| 购物车 | 加入购物车、数量编辑、删除 |
| 我的 | 订单管理、地址管理、微信支付 |

## 2. 功能需求

### 2.0 区域模块（P0 - 新增）

#### 2.0.1 区域选择
- **位置：** 首页顶部或用户首次进入时弹窗选择
- **区域列表：** 东北、华北、华东、华中、华南、西南、西北等
- **记住选择：** 本地缓存用户选择的区域，切换后实时生效
- **切换入口：** 首页顶部区域名称入口，支持快速切换

#### 2.0.2 区域化商品展示
- **首页推荐：** 根据用户所在区域展示不同的推荐商品
- **分类页：** 各区域分类商品可能不同
- **搜索结果：** 优先展示当前区域商品（可选）

#### 2.0.3 区域配置（后台）
- 区域与商品的关联关系（商品可在「区域管理」中按区域勾选可售，对应 `available_regions`）
- 区域默认商品/爆品配置（首页主推/列表规则见 **7.0 首页运营**）
- 区域 **Banner** 差异化配置（可选）：按区域维护一组轮播，与小程序当前所选区域联动
- 区域维度 **首页列表条数上限 N**、**主推模式（自动/指定）** 等与首页展示相关的运营参数（见 7.0）

#### 2.0.4 区域数据结构
```
区域表：
- region_id: 区域ID
- region_name: 区域名称（如"华东"、"东北"）
- region_code: 区域编码（如"EC"、"NE"）

商品表（扩展）：
- available_regions: 适用区域列表
- region_priority: 区域展示优先级
```

### 2.1 首页模块

#### 2.1.1 Banner轮播
- **位置：** 页面顶部
- **数量：** 3-5张Banner图
- **功能：** 自动轮播 + 手动滑动
- **跳转：** 点击 Banner 进入运营配置的落地页，至少支持：**商品详情**、**分类页（指定一级分类）**、**搜索结果页（指定关键词）**；活动/H5 可作为后续扩展。
- **尺寸：** 宽度100%，高度建议 160-200rpx（响应式）；高保真稿可采用更高 Banner 以承载主标题/副文案/按钮样式（以 UI 规范为准）。

#### 2.1.2 首页推荐与列表结构（与原型一致）
- **分区结构：** Banner 与首页内分类（见 2.1.4）之下，分为两个内容区：
  - **主推区（大卡）：** 展示 **1** 款重点商品；含主图、名称、短描述/卖点摘要、现价、划线价（若配置）、主行动（如「立即购买」）。
  - **列表区（宫格）：** 展示除主推外的其余候选商品卡片；卡片含缩略图、名称、现价、划线价（若配置）、营销标签/促销文案（若有）、快捷加购入口；**同一商品在首页仅展示一次**（主推与列表互斥展示）。
- **进入首页候选池的条件（须同时满足）：** 商品 **已上架**；**在当前区域可售**（见 2.0.2、`available_regions`）；且 **`showOnHome = true`（在首页展示）**。关闭「在首页展示」的商品仍可在分类、搜索、购物车等场景出现。
- **排序与截取：** 在 **当前区域 + 用户在首页所选分类（2.1.4）** 条件下，候选商品按 **销量** 降序排列。**主推位** 取法由后台配置：**自动** 取排序后第 1 个；**指定商品** 时固定为该商品（若指定商品不满足可售或不在候选池，则 **临时退回自动** 规则）。**列表区** 在去掉主推后仍按销量排序，但 **仅截取前 N 条** 展示（N 默认 24，可按区域配置，建议范围 9～99）；超出部分不在首页无限加载，文案上引导用户通过 **分类 Tab** 或 **搜索** 浏览全量。
- **布局（宫格列数）：** 早期 PRD 写 **2 列**；当前高保真原型为 **3 列** 以提高一屏信息量。**MVP 允许 2 列或 3 列，以 UI/评审结论为准。**
- **加载更多：** 理想形态为 **下拉加载更多**；在实现成本或列表结构限制下，允许采用 **底部「加载更多」按钮** 分段追加列表区商品，直至达到本区 **N 条上限** 或候选耗尽。
- **空状态：** 无候选时展示「暂无推荐商品」或等价引导（可提示切换区域/分类）。

#### 2.1.3 快捷入口（扩展）
- 类型图标 + 标签
- 可跳转分类页/搜索页
- **高保真补充：** 主推区/列表区标题旁可提供「进分类 ›」「搜索 ›」等文字链，与底部 Tab 形成互补（非必选）。

#### 2.1.4 首页内分类筛选（横滑 Pill）
- **位置：** Banner 下方，横向可滑动分类条（不占底部 Tab）。
- **数据：** 与后台启用的 **一级商品分类** 同源；首项固定为 **「全部」**，其余为各分类名称。
- **行为：** 用户选择某一分类后，**仅在首页内** 按该分类过滤候选商品，再执行 2.1.2 的排序、主推与列表截取逻辑；**不切换** 底部 Tab 的「分类」页。

#### 2.1.5 首页展示开关（字段）
- 商品维度布尔字段 **`showOnHome`（在首页展示）**，后台商品编辑中可勾选；列表页可提供快捷切换（与原型一致）。
- **业务含义：** 为「是否进入首页主推/列表候选池」；关闭后不影响分类、搜索、详情、购物车。

## 3. 业务流程

### 3.1 购物流程图
```
浏览商品 → 加入购物车 / 直接购买 → 结算 → 提交订单 → 微信支付 → 支付成功 → 订单发货 → 确认收货 → 完成
```

### 3.2 关键页面跳转
```
首页 ─┬─→ 分类页（底部Tab）
     ├─→ 搜索页（点击搜索框）
     ├─→ 商品详情（点击商品卡片）
     ├─→ 购物车（底部Tab）
     └─→ 我的（底部Tab）

我的 ─┬─→ 订单列表 → 订单详情
     └─→ 地址管理 → 新增/编辑地址
```

### 3.3 订单状态机与流转规则（P0 - 补齐）

#### 3.3.1 订单状态定义（前台/后台统一）
| 状态 | code | 说明 | 是否可支付 | 是否可取消 | 备注 |
|------|------|------|-----------|-----------|------|
| 待付款 | PENDING_PAY | 已创建订单，等待支付 | 是 | 是 | 到期自动取消 |
| 待发货 | PENDING_SHIP | 已支付，等待商家发货 | 否 | 视规则 | 允许后台发货 |
| 待收货 | SHIPPED | 已发货，运输中 | 否 | 否 | 支持查看物流 |
| 已完成 | FINISHED | 已确认收货/自动收货 | 否 | 否 | 交易完成 |
| 已取消 | CANCELED | 用户取消/超时取消/支付失败关闭 | 否 | 否 | 若已支付则走退款（后续） |

#### 3.3.2 状态流转（MVP）
```
PENDING_PAY ──(支付成功)──> PENDING_SHIP ──(商家发货)──> SHIPPED ──(确认/自动收货)──> FINISHED
     │
     ├─(用户取消)────────> CANCELED
     └─(超时未支付)──────> CANCELED
```

#### 3.3.3 关键时间策略（MVP 默认值，可配置）
- **未支付自动取消**：下单后 \(15\) 分钟未支付 → 自动取消并释放库存（见 3.5）
- **自动确认收货**：发货后 \(7\) 天自动确认收货（如后续要对齐行业，可调整为 10/15 天）

#### 3.3.4 幂等与重复提交（P0）
- **提交订单幂等**：同一用户在同一购物车勾选集合/同一“立即购买”参数下，客户端生成 `client_order_token`，服务端保证同 token 只创建一笔有效订单
- **支付回调幂等**：按 `order_id + paid_transaction_id` 去重；重复回调不重复发货/不重复加库存

### 3.4 支付流程与异常流（P0 - 补齐）

#### 3.4.1 正常流程
```
订单确认页 → 提交订单(创建 PENDING_PAY) → 调用统一下单 → 调起微信支付 → 支付成功回调 → 订单置为 PENDING_SHIP
```

#### 3.4.2 异常与兜底策略（MVP）
- **用户取消支付**：订单保持 `PENDING_PAY`；用户可在订单详情继续支付；超时按 3.3.3 自动取消
- **支付失败/超时**：订单保持 `PENDING_PAY`（或标记失败原因），允许重试支付；超时自动取消
- **回调未到/网络异常**：前端展示“支付结果确认中”，并轮询/查询订单状态（间隔 1s/2s/4s 递增，最多 30s）
- **支付成功但页面未刷新**：以“订单状态查询接口”为准，确保最终一致

#### 3.4.3 金额口径（MVP，预留字段）
- **商品总额**：\(\sum (sku_price \times quantity)\)
- **优惠金额**：MVP 为 0（预留字段）
- **运费**：MVP 为 0（预留字段）
- **实付金额**：商品总额 - 优惠金额 + 运费

### 3.5 库存与扣减规则（P0 - 补齐）

#### 3.5.1 库存口径
- **库存维度**：按 SKU 维度（无 SKU 的商品按商品维度）
- **可售区域**：库存不随区域拆分（MVP），区域仅影响“是否可售/推荐”（见 2.0）

#### 3.5.2 扣减时机（MVP 方案：下单锁库存）
- **创建订单成功（PENDING_PAY）**：锁定库存（冻结数量）
- **支付成功**：将“冻结”转为“已扣减”
- **取消/超时取消**：释放冻结库存

#### 3.5.3 库存不足与并发
- 提交订单前校验库存；并发场景以服务端“锁库存”结果为准
- **库存不足提示**：返回明确提示“库存不足/已售罄”，前端引导用户返回购物车调整数量

### 3.6 地址管理规则（P0 - 补齐）

#### 3.6.1 默认地址规则
- **同一用户仅允许 1 个默认地址**
- **新增时设为默认**：自动取消原默认
- **删除默认地址**：若仍有其他地址，按“最近更新”的地址设为默认；若无则默认为空

#### 3.6.2 下单选址规则（MVP）
- 订单确认页优先展示默认地址
- 无地址时必须先新增地址才能提交订单（阻断提交）
- 订单创建时将地址信息“快照”写入订单（避免后续修改地址影响历史订单）

#### 3.6.3 省市区数据源（MVP）
- 采用静态省市区数据（前端内置或后端接口二选一，评审时确认实现方案）

## 7. 管理后台需求

### 7.0 首页运营（与小程序首页联动）

> 对应高保真原型中的「首页运营」菜单；配置影响当前区域下小程序首页的 **Banner**、**主推** 与 **列表区条数上限**。

#### 7.0.1 区域与 Banner
- 支持按 **销售区域** 切换维护对象；仅展示已启用区域（禁用区域不出现在用户端区域选择器中）。
- **Banner 列表：** 每条含角标/主副标题/促销行/按钮文案、背景图或渐变、跳转类型与目标（商品 ID / 关键词 / 分类名）；支持新增、编辑、删除；支持 **恢复默认 Banner**（演示或灾备用途，正式环境需权限与二次确认策略）。

#### 7.0.2 主推与列表区配置（按区域持久化）
- **主推规则：** **自动** — 当前区域 + 当前用户首页所选分类下，满足「上架 + 在首页展示 + 区域可售」的商品按销量降序，取第 1 个上大卡；**指定** — 大卡固定为所选商品 ID（须满足可售且在候选池内，否则小程序端临时退回自动）。
- **列表区最多商品数：** 不含主推大卡的前提下，列表区最多展示 **N** 个商品卡片（如默认 24，可配置区间建议 9～99）；与 PRD 2.1.2 一致，超出部分不在首页继续加载。
- **保存：** 配置变更保存后，用户切换区域或下次进入首页应生效（具体依赖接口刷新策略）。

### 7.2 商品管理详情

#### 7.2.1 商品列表
- 表格/卡片列表展示；字段至少包含：主图、商品 ID、名称、分类、价格（多规格显示「¥xx起」）、**总库存**、**上架状态**、**是否在首页展示**、操作（编辑等）。
- **筛选（MVP 与原型对齐）：** **按分类筛选**（含「全部」）；**状态 / 关键词筛选、批量上下架、批量删除** 列为后续迭代（仍保留为产品目标，正式排期前以原型为准）。
- **快捷操作（可与原型一致）：** 在列表中直接切换 **上架/下架**、**在首页展示/不展示**（修改 `onShelf`、`showOnHome`）；列表默认排序建议：**已上架且首页展示** 的排在前面，**已下架且不展示** 的排在后面（同态时次序实现自定）。
- 查看销量、库存（库存以 SKU 聚合或按 SKU 在「库存管理」查看）。

#### 7.2.2 商品编辑
- **基本信息：** 名称、描述、主图（支持 **主图 URL** 覆盖系统默认图，无则走默认配图策略）
- **营销展示（与原型对齐，MVP 可选字段）：** **营销标签**（短标签）、**划线价**（原价/对比价展示）、**促销文案**（一行说明，如满减提示）
- **价格：** SKU **售价**（必填）；划线价见上；**会员价** 为后续会员体系能力（当前原型未实现）
- **库存：** SKU 管理、每 SKU **库存数量**、**低库存预警阈值**（低于等于阈值在库存管理中标为预警）
- **关联：** **一级分类**（与分类管理启用列表一致）、**可售区域**（见下）、标签
- **可售区域（与原型交互对齐）：** 支持 **「全国（当前所有已启用区域）」** 或 **「仅某一启用区域」** 两种配置方式，写入商品的 `available_regions`（或等价结构）；禁用区域后商品不可再选该区域。
- **状态：** 上架/下架；**在首页展示**（`showOnHome`）独立开关，含义见 2.1.5

#### 7.2.3 SKU 管理
- 规格管理（颜色、尺码等）
- SKU 列表：规格组合、价格、库存
- SKU 图片
